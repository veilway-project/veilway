# Fuzzing

`config` feeds bytes to `Config::parse`. A config that parses is validated with the shadow check on, serialized back to JSON, parsed again, and must give the same number of validation errors. Needs nightly Rust, so run it in Docker from the repo root:

```
docker run --rm -v "$PWD":/w -v veilway-fuzz-target:/w/fuzz/target -v veilway-fuzz-cargo:/usr/local/cargo -w /w rustlang/rust:nightly sh -c "cargo install cargo-fuzz --locked; mkdir -p /tmp/corpus; cargo fuzz run config /tmp/corpus fuzz/corpus/config -- -max_total_time=300 -dict=fuzz/dict/config.dict -max_len=65536"
```

`packet` feeds bytes to the header parser every decrypted packet goes through (`engine::netstack::parse`), to the same parser as it reads the packet an ICMP error quotes (`engine::netstack::quoted`), and to the answers the node writes itself: the TCP reset, the echo reply and the ICMP errors of every kind (`engine::icmp::error`). A packet that parses must have its upper-layer header inside it, an echo reply must parse and go back to the sender, and an ICMP error must parse, go from the gateway to the sender, quote exactly the start of the packet it answers within the size the RFCs allow, and never be answered with another error. It needs no seeds or dictionary: replace `config` with `packet` in the command above and drop the `fuzz/corpus/config` and `-dict` arguments.

`dns` feeds bytes to the two readers of the node's resolver (`engine::dns::query` and `engine::dns::response`), which see every DNS message from a tunnel and from an upstream server. A query that is read must give REFUSED and SERVFAIL answers that read back as answers to it. Replace `config` with `dns` in the command above, drop the `-dict` argument and use `-max_len=4096`.

`chunk`, `control_stream`, `fuzz_control_server` and `fuzz_control_client` feed bytes to the wire formats in `veilway-proto`. The first bytes of an input are settings, described at the head of each target, and the rest is what is fed. None of them stops at a cryptographic check: the harness seals the plaintext or runs the real other side of the exchange, so the code behind the check sees fuzzed input. All four have seeds, written by `crates/veilway-proto/tests/vectors.py`, and a test in that crate (`tests/seeds.rs`) fails when a seed no longer reads.

- `chunk`: a chunk plaintext that the harness seals and the opener must then read exactly as the reading rules say, a sealed chunk from the wire, items to seal, or a plaintext for the reader and writer alone. A sealer must refuse exactly the items a reader would refuse, and an opener that failed must stay failed. Use `fuzz/corpus/chunk`, no dictionary and `-max_len=20000`.
- `control_stream`: the byte stream of a control channel connection after its opening, in either direction, cut into pieces. It must read the same in pieces as whole, an error must be final, every message that reads must be written back as the same bytes, and a catalogue that is handed out must keep its rules. Use `fuzz/corpus/control_stream`, `-dict=fuzz/dict/control.dict` and `-max_len=20000`.
- `fuzz_control_server`: the node's side of the control channel. A real client runs the exchange while the input picks the secret, one byte to change on the way, the pieces and the time of each call, and the node must open exactly when the secret is right, nothing was changed and the deadline was kept. The rest of the input is then read as requests. With bit 0 of the first byte set, the input goes to a node as it is, and the node must take at most 80 bytes and never open. Use `fuzz/corpus/fuzz_control_server`, `-dict=fuzz/dict/control.dict` and `-max_len=4096`.
- `fuzz_control_client`: the same for the client's side, against a real node or an impostor that has no key. The rest of the input is then read as the node's messages, and what a client would show must stay inside its bounds. Use `fuzz/corpus/fuzz_control_client`, `-dict=fuzz/dict/control.dict` and `-max_len=20000`.

New inputs go to the first corpus directory (`/tmp/corpus`, lost with the container), so the tracked seeds in `fuzz/corpus/config/` stay as written. To keep a good new input, copy it into the seed directory by hand. A crash is saved under `fuzz/artifacts/config/`; shrink it with `cargo fuzz tmin config <file>`.
